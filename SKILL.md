# Strategy Allocation Research Lab

## Generic strategy screening (default)

Read references/evaluation.md and references/appendix.md. For a new user read references/installation.md; resolve script paths relative to this skill directory and use a Python environment with requirements.txt installed. Never assume globally installed dependencies. If asked for a report, the Python script generates an English HTML report without an AI API; add only evidence-grounded narration after inspection. Use scripts/evaluate.py INPUT --strategies COLUMN_A COLUMN_B COLUMN_C --unit decimal --return-type excess --fee-status net --out NEW_DIRECTORY. Choose a new output directory each run. Never silently assume units, fee status or total/excess convention. Existing coursework decimal/net/excess conventions may be reused with disclosure. For total returns require --rf-column naming aligned monthly simple risk-free returns in the same file/units. Do not substitute FX risk factors for another asset class.

Select a CSV or Excel sheet; specify --sheet for Excel. Use arbitrary strategy column names, at least three for the seven-rule comparison. Identify --start and --end explicitly if excluding observations; supplied currency workbook needs --start 1976-02 to exclude its empty initial month. Explain 36-month expanding-history warmup, 6-month momentum, 10% risk target, no cap and signed allocations. Defaults are research assumptions, not optimized settings. Dependencies: numpy, pandas, openpyxl, matplotlib, scikit-learn. scipy is used only for optimization validation tests.

Inspect report.html, summary.csv, periods.csv, exposures.csv, cost_scenarios.csv, activity_proxy.csv, weights.csv and run.json. Check common dates, finite outputs and current estimated risk before writing a narrative. On data validation, undefined signed weights or infeasible MaxRet, stop and explain; never silently change strategy definitions or drop rows. Distinguish target risk from realized risk and an excess-return index from funded total-return wealth.

Explain relative performance versus 1/N, concentration/gross exposures and five-year calendar-block stability, including partial edge blocks. Treat costs as hypothetical incremental charges on target-to-target activity, not drift-adjusted turnover or actual net performance. Do not automatically recommend the best historical Sharpe strategy or claim significance. Report missing risk attribution explicitly. Distinguish observations, economic hypotheses and investment judgments. Preserve unfavorable findings. Record AI-assisted implementation truthfully.

Preserve supplied source data and do not redistribute private/course data without established permission. The old scripts/analyze.py is a capped three-method prototype; use appendix.py for course-only calculation and evaluate.py for general reporting. See references/methodology.md only when comparing the earlier prototype. Use scripts/test_evaluate.py plus existing allocation tests before claiming validation.

## Question 2: cross-sectional pricing

Read references/pricing.md. Use scripts/pricing.py --data-dir DIRECTORY --unit decimal --out NEW_DIRECTORY for the six portfolio workbooks and Factors_Net.xlsx. Treat decimal as the existing coursework convention, disclose it and seek confirmation if provenance is uncertain. Use --grvol-sheet Sheet1 for the supplied GRVOL workbook; portfolio --sheet remains All. Use --grvol PATH only for documented positive global realized volatility LEVELS, never the workbook VOL factor return. With missing global volatility run the baseline and explicitly label the extension unavailable. Do not fabricate data. Explain risk loadings versus prices, full-sample in-sample estimation versus predictive performance, and HAC limitations. Inspect generated CSVs and report before interpreting. Do not add portfolio-exposure integration until requested.

## Appendix E rules (preferred Question 1 mode)

Read references/appendix.md. For all seven methods use scripts/appendix.py INPUT --unit decimal --out NEW_DIRECTORY, with --sheet All --start 1976-02 and optional --factors, --warmup, --momentum and --target. Require or explicitly disclose return-unit convention. Use at least three factors for a literal top-three selection. This mode requires scikit-learn and intentionally uses no cap and permits signed weights. The earlier scripts/analyze.py is a capped three-method prototype, not the seven-rule implementation. Explain the choice before comparing runs. Inspect weights.csv gross/net exposures and estimated risk, plus summary.csv and wealth.png. With three factors disclose TOP3 duplicates SR. Do not relabel it equal weighting. Label MomentumTilt as the student's extension, not an eighth paper rule. On infeasible or undefined weights stop, disclose and discuss a separately labeled specification change rather than silently clipping or substituting. Distinguish implementing Appendix E definitions from replicating the paper's tables.
